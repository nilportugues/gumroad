## Tooling

```bash
cd nextjs
node scripts/parity-debt.ts                 # tagged examples without a fixture, per spec file
node scripts/parity-debt.ts --spec url_redirect   # one spec (substring of the path)
node scripts/parity-debt.ts --json          # same, machine-readable
```

`scripts/parity-debt.ts` parses the specs without Ruby (describe/context nesting from indentation) and matches
each example's full description against the `example` field of the recorded fixtures of the same spec. It
reports `unresolved` for descriptions it cannot resolve (interpolation with no matching fixture, or examples
inside `shared_examples`); the run at `b8fbe3067` has 0 unresolved. It should print `0 without a fixture` when
section 1 is done. Interpolated descriptions (`#{role}`, `#{path}`) are matched as patterns, so a loop that
records only some of its iterations would not be flagged: could not determine whether any does.

## Rack::Attack-throttled routes

`config/initializers/rack_attack.rb` counts requests in Rails' Redis. Node counts what it answers itself (`src/server/controllers/rack-attack.ts`): the same Redis, keys (`rack::attack:<window>:<rule>:<discriminator>`), expiry (`period - now % period + 1`, reset on every hit), limits and backoff tiers, the 429 body, `Retry-After` and the Rack envelope of Rails' responder. There is one counter, called from two places: `processAction` (mutations, handlers, redirects, Inertia visits) and `pageEnvelope` (the full page load of an `inertia` page, which the proxy builds without `processAction`). Both count ahead of the action chain, and `forwardToRails` takes the count back (`DECR`) so a request Node hands back is counted once, by Rails; the proxy takes `pageEnvelope`'s count back before it sends a redirect or a bare 400 through `processAction`. `rack-attack-single-count.test.ts` fails on a second count (recorded INCRBYs, net zero after a hand-back, the two call sites and the importers of the module); breaking `processAction` or `pageEnvelope` to count twice fails it (checked by hand, 4 and 3 failures).

Every rule of the Ruby file is modelled, in its declaration order (production-only ones behind `RACK_ATTACK_PRODUCTION_RULES=1` or `RAILS_ENV=production`). `nextjs/scripts/golden/rack-attack-throttles.rb` loads the initializer a second time as production and dumps every throttle (389 names, limits and periods) and the keys and TTLs Rack::Attack writes for 47 requests; `rack-attack-rules.test.ts` pins both. `rack-attack-throttles.test.ts` mirrors the path and method of every rule (the path literals are read back from the Ruby file) and fails when a `routes.json` entry matches one that Node does not count (`countsInNode`: a mutation, handler, redirect or `inertia` page) or that is not justified in `ALLOWED`.

What the lane added to the counter (lane 25: `gumroad_test_25`, `gumroad_replay_25`, Redis 1-4 recording and 3/5 replay, container `gr-ruby-c25c`, `PARITY_ES_INDEX_SUFFIX=-c25c`):

- `invalid_params` (5 per minute, 7 tiers): a `%` that does not start a hex escape, more than 4096 pairs, or 32 or more nested brackets in a key. Rack leaves invalid UTF-8 alone (the golden counts nothing for it), and Node's parser cannot read it, so that request hands back. The rules that read a parameter skip an unparseable request, as the backoff wrapper's `rescue` does.
- The Warden-user rules (`/settings/totp/confirm`, `/settings/passkeys`, `/settings/passkeys/registration_options`, the marketing execute): the user comes from the session cookie (`resolveRequestAuth`). A request signed in by the remember cookie alone has no Warden user at that point in Rails (the cookie is read by a strategy in the controller), so it is not counted, and the proxy hands it to Rails anyway. The totp rule counts a signed-out request under the empty identifier, as `"#{nil}"` does.
- The product `PUT`/`PATCH` rules with the VIP buckets (`/vip/ip`, `/vip/params`). Node asks the database for the token's owner and sums `payments.completed`; Rails caches that answer for 10 minutes (`rack_attack:vip_token:<sha>` in `Rails.cache`), so a creator who just crossed $5,000 counts as a VIP in Node up to 10 minutes earlier. Node does not serve the product writes, so this only matters once they are ported.
- Brand accounts, `/users/auth/facebook`, `/`, `/discover_search`, `/purchases` (two rules), `/stripe/setup_intents`, `/settings/credit_card`, the help contact form, the OAuth device and token rules, passkey login, `/:username/affiliate_requests`, the AI product details generation and the ACME challenge (keyed on the path too, so every token has its own budget).
